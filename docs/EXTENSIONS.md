# 扩展设计

先让核心循环稳定：工作 → 全屏活动 → 用户确认 → 工作。新功能围绕这个循环接入，避免让外部服务影响计时。

## 内容提供器

`src/main/extensions/index.ts` 定义 `ContentProvider` 与 `ContentContext`，并提供一个无需网络的本地实现。目前主进程使用 `dailyContent`。增加文案来源时实现 `getContent(context)`，然后在主进程选择提供器即可。

当前接口同步返回，用于内置内容。未来 AI 文案应使用独立异步服务提前生成、超时后回退到本地内容，再交由同步提供器读取缓存，不要在 250ms 的快照循环里发网络请求。API Key 留在主进程侧，使用系统凭据存储，不写入前端或提交仓库。

## 今日计划

建议新增 `shared/plans.ts` 类型、独立计划存储与经过验证的 IPC API，在渲染端增加页面。计划完成情况与活动统计分开保存，再按需要在活动提醒中提示下一项任务。

## 角色陪伴

提醒窗口已独立于主窗口，可在提醒页面替换 `break-art` 区域。新增角色资源清单，记录本地图片 / 动画、动作与署名。先从打包的本地素材做起，后续再实现导入和资源校验。不要直接执行导入包中的 JavaScript。

## 插件边界

`renderer/src/extensions.ts` 是展示目录，`main/extensions` 是内容接口。此版本不是支持任意第三方代码的插件加载器。等扩展需求明确后，再抽出生命周期（启动、活动开始、活动完成）、权限声明、配置和版本迁移。未来需要更完整历史数据时可将 Store 替换成 SQLite，保持前端 API 不变。
